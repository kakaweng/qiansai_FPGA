## 应用

先关闭旧预览，在Ubuntu执行：

```bash
sudo -v && bash /mnt/hgfs/pcie_host/update_junction_route_rk3568.sh
```

看到 `JUNCTION_ROUTE_PASS` 后，在预览终端执行：

```bash
bash /mnt/hgfs/pcie_host/preview_pie_anticipation.sh
```

本轮含 `pedestrian_gate.h` 板端匹配修正，需要执行更新脚本。脚本先回归，再编译、安装、启动，复用原模型；预览启动器会复制新增 `junction_route.py` 到Ubuntu本地目录。共享目录丢失时需先恢复挂载。

## 行为

| 情况 | 普通预演的行为 |
| --- | --- |
| 右转 | 检查驶入横道、右转出口横道与车辆路线的关系。左侧、远端及路线外行人不会仅凭人数触发礼让。 |
| 左转/直行 | 分别检查驶入横道和左转/直行出口横道。 |
| 路线内行人已由板端确认接触真实横道，证据仍新鲜 | 停车，显示“有人，停车礼让”。 |
| 检测到路线内行人，横道匹配尚未确认或正在短时保持 | 停车，显示“可能有人，停车确认”。不将推测冒充确认。 |
| 行人结果无效、过期、刚恢复、只有人数没有位置 | 在下一条相关横道前等待确认，不把缺失结果解释成无人。 |
| 短时漏检 | 保留目标及冲突；与原2.6秒显示保持一致，避免车辆穿过仍显示的目标。 |
| 恢复预演 | 至少两次新目标观测、源时间跨度至少500ms；已无路线冲突，距最近冲突至少1.2秒，并且保持图标不再占用路线。重复HTTP、旧序号或时间倒退不计数；分析断档后重新确认。 |
| 已进入转弯阶段才出现行人 | 持续检查，立即停在当前位置；取消旧版24000处结束礼让检查的限制。 |
| F违规预演 | 唯一主动绕过本地冲突的操作，持续显示违规；G普通开始/继续恢复冲突检查。 |

车辆路线、车身朝向与冲突检查共用 `junction_scene.route_path/route_pose`。检查包含车辆宽度、前后长度、余量与未来路线；不是仅检查车中心点。相关横道有边框提示，涉及冲突的行人有橙色地面环，中文卡片显示等待原因。所有目标仍检查，界面六人显示上限不会漏掉其余已跟踪行人的冲突。

## 两种证据期限

板端真实接触规则继续要求行人750ms、横道850ms、两源时间差350ms及多次独立观测。小范围脚点分割空洞允许两侧真实像素支持后补足，最大水平3像素、垂直2像素（320×180平面）；单侧白条、大空洞和整片凸包不算接触。

本地预演允许1500ms以内的实际检测用于谨慎观察，以适应现有约900ms推理/交付。超过750ms的目标不能据此宣称“当前已确认接触”，仍只作为可能冲突或保持。超过期限的结果不能作为新的无人证据。这些本地结果不写回板端驾驶许可、交通灯或变道判定。

## 验证范围与限制

路口仍是模板加检测驱动的示意布局；左右横道归属、地面位置、路线长度和缓冲量使用示意单位，不代表真实距离、实际碰撞时间或完整路口重建。现有模型漏检、错误归属仍会影响预演。真实空间标定与难例微调属于后续改进。

本轮开发机回归覆盖路线选择、路径外人群、确认/疑似冲突、晚出现行人、漏检保持、连续空帧恢复、过期/重复/乱序、违规例外和界面反馈。另使用PIE set01/video_0004原片160秒起片段、实际Windows YOLO及900ms模拟交付进行离线回放，产物在 `rk3568_crosswalk_deploy/presentation_review/route_conflict/`。离线渲染与构造输入规则测试不替代RK3568实际显示验收。
