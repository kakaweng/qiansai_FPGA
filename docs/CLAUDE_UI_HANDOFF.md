## 项目与运行环境

- Windows 工程目录：`F:\B_file\jichuangsai\Pango_FPGA\09_pcie_test\pcie_host`。
- 真实预览运行在 Ubuntu 虚拟机，工程通过 VMware 共享目录 `/mnt/hgfs/pcie_host` 访问。
- FPGA 接收正前方 HDMI 视频，经 PCIe 交给 RK3568。RK3568 完成车道、车辆、行人、交通灯识别，并运行辅助驾驶 C 状态机。
- Ubuntu 接收已叠加识别结果的视频，通过 HTTP 读取板端状态、提交操作，在同一个窗口显示视频和中文驾驶面板。
- 当前任务针对独立的 HDMI 单路 `front_p1` 模式。工程也有三路、旧版单路等入口，需要保持其兼容性。
- 当前界面基于 Python、OpenCV HighGUI、Pillow、NumPy。优先在现有技术栈内完成，运行目标是 Ubuntu，Windows 可进行离线布局预览和测试。

## 用户希望改善的体验

1. 视频与辅助驾驶状态保持在同一个窗口，视频清楚、占据足够面积，演示时能迅速看懂。
2. 清晰呈现：检测是否运行、当前灯色、路口方向、模拟车速、左右边界、变道请求及反馈。
3. 用明确的层级、留白、字体和图形表达主次，减少大段文字和按钮拥挤。可以重排面板和交互分组。
4. 正常状态、需要人工观察、报警、结果保持、待确认、断流应容易区分。颜色与文字/图标配合。
5. 常用操作容易找到：开始/停止、左/右变道、模拟停车。路口方向、选灯、模拟起步组成清楚的流程；强行行驶演示与常规操作有视觉区分。
6. 点击视频里的 LIGHT 即可选择交通灯。识别结果自动显示，不增加每次识别前必须框选、选方向的步骤。
7. 维持实时预览流畅度，不因美化引入阻塞网络请求、重复加载字体或高成本逐帧面板绘制。

可以自主选择协调的配色、卡片、图标和布局。重点是实际可用的中文驾驶演示界面。所有文字、图标和静态资源应本地可用。

## 修改范围

主要修改 `front_p1_preview.py`；必要时可调整 Python 显示入口、共用界面代码、前端资源同步脚本，以及对应测试和界面说明。

本任务不改模型权重、RKNN 转换/量化、车道 A1 参数、灯色算法、板端 C 状态机、FPGA/驱动、视频数据协议或控制 API。界面按钮仍发送既有动作，判定结果仍来自现有板端状态。不要以本地假状态替代真实连接。

不要为了美化重写整个工程或默认迁移到浏览器/新 GUI 框架。若认为现有框架确实无法满足某项关键需求，请先说明具体限制与迁移成本；现有技术栈能完成的部分直接实施。

## 必须保留的功能语义

| 功能 | 当前行为 |
|---|---|
| 开始/停止 | 空格开始、X 停止辅助判断；不控制 Windows 原视频的暂停或回放 |
| 自动灯色 | 开始后自动显示；多灯颜色冲突时提示选择对应灯 |
| 路口方向 | J / I / L 分别是左转 / 直行 / 右转。方向由用户指定，模型尚不自动判断箭头方向及灯的车道归属 |
| 选灯 | 直接点击 LIGHT，兼容拖框；T 可显示选灯提示；C 恢复自动识别 |
| 模拟行驶 | G 确认灯并提交起步请求；B 模拟停车；F 强行行驶演示最多 2 秒。车速、方向 LED 为模拟状态 |
| 变道 | A / D 提交左 / 右变道请求；K 取消；请求持续最多 10 秒 |
| 实线/虚线 | 实线阻止变道并报警；虚线仅表示需要继续人工确认侧后方，不显示“已确认安全可变道” |
| 车道保持 | P1 v2 每侧最后确认结果最多保留 1500ms，显示“保持”；未知/重复模型帧不续期，新确认线型更新，超时/停止/断流清除 |
| 灯色保持 | 已确认颜色最多显示保持 1500ms；有效绿色证据要求与显示保持不同，“绿灯（保持）”不代表可依据旧证据继续模拟通行 |
| 退出/截图 | Q 或 Esc 退出，S 截图；鼠标按钮和已有快捷键均可使用 |

可以优化文案，但保留上述含义。已有 `p1_presentation()` 是显示与时效处理的入口，不因重排控件绕过它。P1 v1/v2 的兼容处理保留。

## 实现时特别留意

- 视频当前由板端输出 `1280×480` BGR 画布，中间有效 HDMI 内容约为 `853×480`，左侧偏移 `213`。当前面板追加后总图像为 `1280×850`。总窗口布局可以调整，但板端输入数据格式保持不变。
- 选灯和 SELECTED 框必须使用同一套坐标变换，后端坐标是相对有效 HDMI 内容的 `0..10000`。若移动、缩放或重新裁排视频，同步更新鼠标坐标、黑边排除、拖框、蓝框和按钮命中测试。可集中管理几何参数。
- 当前 HTTP 默认地址 `http://127.0.0.1:9011`，视频地址 `127.0.0.1:9004`，经 HDC 转发。沿用 `FrontP1Client` / `DriveClient` 的后台线程和非阻塞命令队列，不在绘制/点击回调里直接请求网络。
- 现有视频接收为后台最新帧；面板常规最多约 5Hz 刷新，状态变化及时重绘，保留缓存思路。关闭窗口能停止后台线程。
- 继续从板端 `drive.p1`、`stable_line`、`line_held`、`line_age_ms` 等字段展示结果。不要只读旧 `line` 字段导致短时漏检再次跳变，也不要以全局 `drive.signal` 覆盖选定灯状态。
- `snapshot.received_at` 与前端 `now` 使用本机 monotonic 时钟；板端通过年龄字段传递结果时效，不直接混算不同机器的时钟。
- 共用模块的修改需要验证旧单路/多路入口，不要影响旧类构造参数。
- 中文字体必须覆盖新增文字。检查 `preview_fonts/PangoPreviewSans.ttf` 的字形；必要时使用 `tools/build_preview_font.py` 重新生成并保留 OFL 许可。字体生成只用于开发，预览启动时不下载字体。
- 若新增 Python 模块或静态资源，更新 `preview_front_p1.sh` 的显式同步清单，保证 Ubuntu 本地副本实际拿到新文件，避免 Windows 改了而 Ubuntu 仍运行旧界面。

5. 实际打开生成的预览图检查中文缺字、文字截断、重叠、选灯坐标和按钮区域。
6. 说明修改文件、验证结果、Ubuntu 启动命令；区分离线检查与真实 RK3568 验证。
