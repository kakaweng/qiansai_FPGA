# HDMI 路口冻结与三秒推演（2026-11-02）

当前预览新增独立快照模式：正常播放时积累行人运动；在Windows暂停原片后，收齐静止画面的对象与斑马线结果；固定场景，再用本地模拟时钟播放三秒轨迹。沿用原深色界面，不改FPGA、RKNN权重、板端服务或控制协议。

**N不会控制Windows播放器。** 此版按已经确认的操作流程，由用户先暂停HDMI原视频，RK3568继续检测这一张静止输入；Ubuntu预览负责冻结与预演。完成的快照不因实时感知结果过期而清空，返回实时模式后清除快照，不把预测当作新的检测证据。

2026-11-02追加修正：暂停源视频后仍频繁提示“画面仍在变化”。旧版直接比较带板端识别叠加的灰度图，动态框、HOLD颜色和车道着色会重置稳定计时并清空暂停前历史。现改为识别板端不透明线条调色板，并按实际18%车道区域着色、45%线型着色及其叠加顺序比较可能的底图像素；不把任意亮度变化拟合成静止。固定参照图保留慢速累积位移，分块检查保留对静止背景上人物移动的响应。检测结果的来源、时间配对与有效性条件保持。

## 更新与使用

保持当前板端检测服务运行，关闭旧预览。在Ubuntu执行：

```bash
bash /mnt/hgfs/pcie_host/update_frozen_junction_preview.sh
```

看到 `FROZEN_JUNCTION_PREVIEW_PASS` 后启动：

```bash
bash /mnt/hgfs/pcie_host/preview_pie_anticipation.sh
```

启动器会同步Python模块与字体到Ubuntu本地目录；此更新不重新训练、转换模型或切换板端服务。正常识别与A/D变道请求继续使用原链路。

| 顺序/按键 | 操作 |
| --- | --- |
| 先正常播放至少2～3秒 | 预览保持检测，积累真实行人运动；直接拖到一个时间点并立即暂停可能没有行为历史 |
| Windows播放器暂停 | HDMI输入保持这一张画面；不要点击预览的“停止检测” |
| M | 进入冻结路口界面，暂不播放人物动画 |
| N / 冻结并分析 | 等待画面稳定、行人与横道结果到达；成功显示“快照已就绪” |
| J / I / L | 左转/直行/右转；切换方向重置模拟时间，人物初始位置保持不变 |
| G | 播放/继续三秒推演；车辆礼让时行人仍继续模拟移动 |
| B | 暂停整个推演，包括人物与车辆 |
| R | 回到同一快照的0秒，方便重复比较 |
| N | 丢弃旧快照，重新分析当前输入 |
| M / 返回识别 | 结束快照模式，恢复实时视图；然后可以在Windows继续视频 |

分析最多等待12秒。持续提示画面变化时，先检查源视频是否暂停；连接中断、没有斑马线分割接口、结果来源/时间不匹配时不生成快照。失败原因显示在场景卡中，按N重试。完成快照后即使连接断开，仍可进行明确标记的本地预演。

## 实现与信息边界

| 部分 | 当前策略 |
| --- | --- |
| 播放时记录 | 缓存最近6.5秒的独立对象结果及运动状态，使用上一版带背景补偿的运动历史 |
| 暂停识别 | 192×108采样、排除板端已知细线框/标签，并核对已知车道混色后检查至少450ms稳定；固定参照加全局/局部分块运动检查，这是稳定性检查，不等于已与外部播放器握手 |
| 预览负担 | 相同接收帧不重复比较，画面检查最多12.5Hz；独立对象结果照常进入历史，不降低模型检测频率 |
| 历史保留 | 在画面稳定时单独保存之前约1.7秒的行为信息，即使用户暂停后等待较久也不会被重复静止结果覆盖 |
| 收齐当前结果 | 对象与分割必须同producer，均来自画面稳定之后，互差不超过350ms；结果与当前画面相差最多2.5秒，控制连接必须有效 |
| 几何 | 对经过上述验证的静止输入单独提取空间横道带，不伪造新鲜时间来绕过实时校验；冻结几何标记SNAPSHOT |
| 侧方横道 | 对略跨画面中线、仍偏侧方且较平直的窄横道作侧方估计，仅用于冻结场景；估计位置保留虚环，不改实时关联器策略 |
| 人物位置 | 优先当前分割横道与脚点；无支持时保留位置估计，已确认横穿可保留暂停前的车前横道运动估计；不读取官方标注安排人物 |
| 未来运动 | 方向和相对速度来自暂停前的背景补偿位移；缺少有效历史时保持原位；近一秒实线、更远虚线，均为推测 |
| 路线冲突 | 在同一模拟时刻检查本车轮廓与行人/骑行者的位置，预测交汇时本车等待；人物时钟继续推进。仅指三秒示意范围，不表示实际通行许可 |
| 信号灯 | 冻结有效灯色供直行/左转演示；红/黄灯保持等待，右转继续按用户确认的路径行人规则；快照中的灯不会自动变绿 |
| PIE | 保存冻结时的有效接口状态/分数，仍为未校准提前横穿分数；冻结不补足5Hz采样合同，不把同一图片重复计作运动历史 |

场景时间和路线进度为示意量，卡片显示“推演时间”，不把路线参数当作实测车速。道路仍为模板，缺少相机标定、完整路缘与拓扑时，不能保证每个目标的横道归属和真实距离；冻结主要解决结果追赶、历史丢失与演示跳动，不能让单帧缺失信息自动变准确。

## 验证

本机Windows完整自动回归180项通过，包含17项快照回归。追加用例覆盖动态YOLO框/标签、HOLD灰框、车道区域及线型着色不重置暂停锚点；轻微像素噪声；动态叠加下长期保留暂停前历史；真实平移、每次1像素的累积漂移、静止背景上的人物移动；源切换与时钟回退。原有同源/时间配对、无效/过期mask、超时、重播、礼让、信号规则、断线后本地预演等回归继续通过。Bash入口语法检查通过。

使用原片的真实YOLO与Mapillary ONNX缓存输出，模拟900ms结果交付延迟；未读取PIE行为XML，也没有按视频名/时间点在生产代码中预置人物。两段实际源画面回放：

| 片段 | 离线结果 |
| --- | --- |
| set01/video_0004，162秒暂停 | 暂停后约0.92秒完成快照；6名行人和5个其他目标固定，3个目标保留可用运动；右侧横道相关人物触发礼让，三秒内本车保持等待 |
| 同视频，53秒暂停 | 暂停后约0.92秒完成快照；红衣行人保留右→左横穿，在三秒示意中继续移动；存在礼让阶段，随后预测路径清空，预演继续 |

两段均没有向板端发送场景操作指令，报告未发现文字截断。以上为开发片段回归，**不是独立数据集准确率、真实未来轨迹验证或RK3568实机验收**。

本次还对上述两段原片加入每次刷新都会变化的**模拟板端叠加**（独立压力绘图，不是该帧真实模型输出框），复现旧版误报。修正后两处在暂停后约0.92秒就绪，停住后叠加变化不再重置锚点；暂停前的原片播放均保持运动判定。结果分别保留11/6个目标与3/2个可用运动，两段仍出现礼让；对象与横道源时刻一致，时间差0ms。输出位于 `frozen_overlay_0004_162/`、`frozen_overlay_0004_53/`，报告额外记录 `picture_change`、`stable_ms` 和模拟叠加标记。

输出位于 `rk3568_crosswalk_deploy/alignment_review/frozen_0004_162/`、`frozen_0004_53/`，包含 `preview.mp4`、`ready.png`、`playing.png`、`complete.png` 和 `review.json`。报告记录冻结源时刻、对象与横道序号/时间差、初始人物位置、运动依据和逐帧推演状态。
