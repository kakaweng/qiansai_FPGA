# 车道边界判定策略

## 当前目标

当前 Windows 预览不再把“识别出完整车道数量、从左数第几条”作为虚实线判断的前置条件。系统分别寻找画面中心左右最近的边界，直接输出：

| 输出 | 含义 |
| --- | --- |
| `solid` | 当前边界连续标线证据足够，不能跨越 |
| `dashed` | 当前边界存在分离的标线段和内部间隙，可以进入变道条件判断 |
| `unknown` | 当前帧没有足够的边界或原图标线证据 |

单侧边界可以独立确认；另一侧缺失不会把已经确认的一侧强制改成未知。任意位置出现一条虚线也不会直接放行变道，仍要检查该线是否属于请求方向、邻道车辆是否冲突、分析结果是否新鲜，以及是否处于停车或礼让状态。

## 时序规则

- 同一边界需要 3 次真实、同类观察才成为当前确认类型。Windows 模式允许中间短暂未知，但两次真实线型证据间隔不得超过 500ms；默认不暂存模式仍要求连续帧。
- Windows 视频入口对同一边界允许最多 800ms 的短暂显示暂存；暂存证据会标记 `held=true` 和 `age_ms`。
- 暂存结果只用于让预览画面连续，变道许可把它视为 `unknown`，不会用暂存虚线自动放行。
- 未知帧不刷新确认时间；超过 500ms 没有真实线型证据时，未完成的确认累计会过期。
- 新边界轨迹、已检测到相反线型或车道变化事件会清除旧确认，避免把旧虚线带到新实线上。
- `BoundaryTypeMonitor` 的默认 `hold_ms=0`，板端和其他调用保持不暂存；Windows 入口显式使用 `hold_ms=800`。

A1 板端验证例外：`scene_v4` 将已确认边界的显示保持设为 550ms，并允许同一几何边界的一次未知观察继续显示 `HOLD`。该保持结果的 `decision_type` 仍为 `unknown`，不会用于变道许可；连续第二次未知、几何移动或超过550ms仍会清除。

## 证据来源与限制

虚实线类别来自当前图像的白色/黄色标线采样和行程间隙，不能从 YOLOP 的车道前景掩膜连续性推断虚实线。YOLOP 官方权重是在 BDD100K 上训练的车道前景模型，不直接输出 `solid`/`dashed` 类别。

本次修改处理短暂遮挡、确认累计反复中断和历史结果误用问题。单侧分类无需完整车道配对，但边界位置仍来自现有几何提取，边界定位失败的根因尚未解决，不等同于模型准确率提升。路口、弯道、强遮挡、低清晰度和原图根本没有可见标线时，系统仍会输出 `unknown`。

## 何时训练

先用当前单侧边界、轨迹身份和时序规则收集误检/漏检样本。若肉眼能看到标线，而模型前景或局部边界长期缺失，再训练面向左右边界的轻量分割模型；若边界位置正确但原图规则不能稳定区分虚实线，再使用具有 `solid`/`dashed` 标注的模型替代分类规则。

BDD100K 的车道标线标注可包含 `laneStyle`（实线/虚线）属性；需要核对本机是否具有对应图像和完整标注，并转换成训练标签。仅有图片或 YOLOP 前景掩膜不能直接训练虚实线分类。训练可在 Windows GPU 上完成；导出、量化、RKNN 转换和板端延迟仍需在 RK3568 上验收。
