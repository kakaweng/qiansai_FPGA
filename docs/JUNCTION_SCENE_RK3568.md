## 界面与行为

| 模式 | 功能 |
|---|---|
| 实景识别 | 保留大视频、灯色、左右边界与变道请求，隐藏原先详细的模拟驾驶按钮 |
| 路口演示 | 左侧真实 HDMI 视频，中间 2.5D 路口，右侧状态卡片；左/直/右路线、停车、通行、违规报警与虚拟方向 LED |

按 M 手动进入路口演示；本版没有自动识别“进入路口”。道路、停止线和本车是预设场景；真实检测并且落点可定位的行人、非机动车和车辆以相对位置叠加，保留跟踪编号、短时保持和过期清除。P 表示行人，B 表示非机动车/摩托车，V 表示车辆；保持时淡化并带 `~`。模拟本车转弯不会把真实目标带着移动。目标位置是前视相对示意，不是测量出的路口三维坐标，也不能据此确定已经处于斑马线上。虚拟车辆的位置和车速不代表实际车辆，也不控制原视频播放。

场景由 RK3568 C 控制器驱动：

- 默认选择直行，可在演示未运行且尚未进入路口时切换左转/直行/右转；换路线重置车辆位置。
- G 开始后，车辆接近停止线。左转/直行/右转专用箭头灯模式中，只有一盏新鲜候选灯时，开始操作同时确认这盏灯；多盏灯需要点击视频里的对应 LIGHT。不会在运行途中默默选择后来出现的新灯。
- 左转、直行和右转专用箭头灯模式：只有绑定目标、当前有效且已确认的绿灯允许进入。红灯、黄灯、未知、保持中的绿色和未选灯都不能正常进入。
- 右转先按 E 或点“右转规则”按钮，在“待确认 → 圆灯 → 右转专用箭头灯 → 禁止右转”中循环选择。模型尚不能可靠地区分灯型或识别禁右标志，规则须由操作者确认；运行中或已进入路口时不能修改。
- 圆灯模式表示已人工确认无禁止右转等限制：不会仅因圆形红灯或多圆灯颜色冲突而硬停车，以约7km/h低速演示，并持续提示让行行人、非机动车及直行车辆。未确认规则时等待，禁止右转时不进入。当前未接入可靠的路口冲突区和优先权判定，因此此模式不输出真实道路的安全通行许可，不把“未检测到行人”当成安全依据。
- 一旦获准进入路口，车辆沿已确定的路线完成通过，之后灯色变化或灯目标离开视野不会让它停在路口中间。
- B 暂停虚拟车辆，G 继续；暂停和连接中断都可停止已经进入路口的虚拟车辆。断流恢复后需明确按 G，不自动恢复运动。
- R 重置车辆位置和本次违规标记，保留方向及仍有效的灯选择。完成后不会自动循环，需要重置再开始。
- F 只在车辆位于停止线前、对应灯被确认为红/黄时执行违规演示；车辆越线通行，红色场景边框和违规状态持续至重置。重复按 F 不重复记录同一次事件。
- 车道1.5秒保持及 A/D/K 实景变道请求继续有效；虚线反馈仍需人工确认侧后方。

## 更新到 RK3568

前提：沿用已运行的 HDMI 单路链路，共享目录已挂载，HDC 和驱动已就绪。关闭旧预览，Ubuntu 执行：

```bash
sudo -v && bash /mnt/hgfs/pcie_host/integrate_front_p1_rk3568.sh
```

成功标志 `FRONT_P1_PASS`。脚本会测试和重编译控制器、更新程序并启动，复用原模型。此次包含板端场景状态机，不能仅重开预览应用全部改动；不需要重新生成 FPGA 位流。

另一个 Ubuntu 终端：

```bash
bash /mnt/hgfs/pcie_host/preview_front_p1.sh
```

操作顺序：空格开始检测 → M进入路口 → J/I/L选择路线 → 右转时按E确认规则，灯控路线必要时点选交通灯 → G开始。切换规则先B暂停；已进入路口须R重置。窗口中的按钮与快捷键等效。

如果正在使用新增的 PIE 板端实验分数版，保留该入口更新：`sudo -v && bash /mnt/hgfs/pcie_host/integrate_pie_anticipation_rk3568.sh`，然后运行 `bash /mnt/hgfs/pcie_host/preview_pie_anticipation.sh`。它包含相同的路口修复并保留已有预测分数卡，不需要重新训练或转换模型。

| 按键 | 功能 |
|---|---|
| 空格 / X | 开始 / 停止检测；开始检测会新建检测会话 |
| M | 进入路口 / 返回识别；返回识别会停止本次场景运动 |
| J / I / L | 选择左转 / 直行 / 右转模拟路线 |
| E | 右转规则：待确认 / 圆灯让行 / 右转专用箭头灯 / 禁止右转 |
| G | 开始 / 继续场景 |
| B | 暂停车辆 |
| R | 重置场景 |
| F | 在红/黄灯停止线前进行违规通行演示 |
| T / C | 选灯提示 / 恢复自动灯色；也可直接点击 LIGHT 或拖框 |
| A / D / K | 真实视频左/右变道请求 / 取消；两种模式均支持 |
| S / Q / Esc | 截图 / 退出预览 |

更新成功后，板端重启使用现有流程恢复驱动和转发，然后执行：

```bash
sudo -v && bash /mnt/hgfs/pcie_host/deploy_front_p1_rk3568.sh start
bash /mnt/hgfs/pcie_host/preview_front_p1.sh
```

日志仍使用 `deploy_front_p1_rk3568.sh log`，状态变化日志增加 `scene`、`phase`、`run`、`violation`。

## Windows 离线交互

```powershell
Set-Location 'F:\B_file\jichuangsai\Pango_FPGA\09_pcie_test\pcie_host'
python preview_junction_demo.py
```

离线程序在随机本地端口启动本机 C 控制器，使用与板端相同的状态机、HTTP 操作及 UDP 感知输入；灯色输入是明确标注的构造数据，没有执行模型推理，也不会连接 RK3568。

- 1 红灯、2 黄灯、3 绿灯、0 未知。
- 自动开始检测并打开路口模式；G开始后等待约5秒，到停止线前观察红灯停车，再按3观察通行。
- J/I/L、G/B/R/F/M 与实机界面相同。
- 本机离线控制器已编译在 `rk3568_front_p1_deploy/host/rk_front_p1_control.exe`。若需要重编译，执行 `powershell -ExecutionPolicy Bypass -File .\build_junction_demo.ps1`；使用工程已有的 Zig 工具链。

界面检查入口：`ui_preview_junction/index.html`，12种构造状态截图。
动画：`ui_preview_junction/junction_demo_offline.mp4`，20秒离线 C 控制器联调录制，包含红灯等待、绿灯左转、已进入后的灯色变化及完成。

## 实现接口与后续 FPGA 按键

屏幕按钮使用现有 `POST /api/drive?action=...`，新增以下场景动作：

`scene_open`、`scene_close`、`scene_start`、`scene_pause`、`scene_reset`、`scene_force`。

方向继续使用 `turn_left`、`straight`、`turn_right`。规则动作使用 `rule_unknown`、`rule_circle`、`rule_arrow`、`rule_prohibited`，状态字段为 `drive.p1.right_rule`（`unknown/circle/arrow/prohibited`）。新增阶段 `WAIT_RIGHT_RULE`、`RIGHT_PROHIBITED`、`RIGHT_YIELD`。后续 FPGA 按键适配层可将按键事件映射到同一 `front_p1_action()` 入口。当前没有修改 FPGA，也没有实体按键或实体 LED 接入。

`drive.p1.scene` 是 version=1 的场景协议，包含启用/运行状态、阶段、位置、速度、已进入标记、违规标记和场景编号。位置范围0..60000（场景毫米），停止线15000；这些距离为预设动画尺度，不是从视频估测的距离。

Ubuntu 只依据返回的位置绘图；对新鲜快照最多做150ms的显示插值，未获准进入时插值也不会越过停止线。快照超过500ms或视频断流时停止动画。道路背景与面板缓存，运动不触发整窗文字重绘。
