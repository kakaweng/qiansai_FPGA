## 三种视图

| 操作 | 行为 |
|---|---|
| 默认实时映射 | 左侧HDMI检测画面，中间本车固定的2.5D，右侧原有灯色及变道反馈 |
| V / 大画面 | 切换大视频识别与实时映射 |
| M / 路口演示 | 进入原有预设路口交互；J/I/L、G/B/R/F继续有效 |
| 路口模式按V | 返回实时映射并停止场景运动 |
| A / D / K | 请求左／右变道、取消，仍由板端规则判断 |
| T / C | 选交通灯、恢复自动；在视频中直接点击LIGHT仍有效 |

实时映射与路口演示使用不同坐标：实时映射本车固定，目标来自实际检测；路口演示道路为预设，车辆位置由板端模拟状态机驱动。两者不拼成虚假的共同场景。

## 视频区域和地面标定

默认提供相对位置示意，明确标注“默认示意”。不显示米数，也不把2.5D目标位置用于碰撞或通行许可。

1. HDMI全屏播放前视视频，隐藏播放器控制栏。若含黑边／任务栏，按 **U**，在暂停的预览画面中拖框选择实际视频内容。
2. 在车道清楚的直路按 **H**，暂停当前预览画面；依次点击同一车道的 **远左、远右、近右、近左** 四点。远端两点选在同一横截面，近端两点也应对应同一横截面。
3. 第四点完成后校验凸四边形和远近关系，保存后自动恢复视频。无效四点不会覆盖旧标定。再次按H/U可取消。
4. **O** 恢复全画面默认示意。换相机、视频裁剪或窗口布局时重新检查标定。

配置保存至运行副本同目录的 `front_ground_projection.json`；Ubuntu默认位置 `$HOME/pcie_lane_rk3568/front_ground_projection.json`。预览启动同步源码时不会覆盖此配置。

这是平路假设下的四点单应变换，展示相对方位与远近；纵向显示采用非线性压缩便于观看，图上格线不是米制网格。坡道、相机俯仰、转弯和目标遮挡都会带来误差。框底触及有效视频底部或投影超出范围时，显示“部分目标落点不可定位”，不强行放在路面。道路网格是示意背景，不代表已识别可行驶区域；没有曲线时不填造车道。

## 感知与时效

| 内容 | 实现 |
|---|---|
| 板端模型 | 原LR-ASPP与YOLO；权重、A1判定、灯色规则保持原有配置 |
| 真实车道 | 导出解码器最多12条候选边界，每条12点，优先本车两侧；不是全部分割像素，也不是完整路口拓扑 |
| 真实目标 | 导出最多40个行人、车辆、骑行目标；不导出交通灯至地面位置 |
| 数据接口 | 本机UDP9013发送FWM1，最大1176字节；现有 `/api/status` 增加 `world` 字段，HDC转发保持原配置 |
| 时间 | 各自携带源图采集序号、时间；界面显示LANE、OBJ结果年龄及GAP；GAP超过350ms提示时间差，不计算融合冲突判断 |
| 跟踪 | 预览端按图像位置、框重叠及类别进行一对一匹配；车道按重叠纵向范围匹配；持续编号不是永久身份 |
| 平滑 | 位置滤波＋最多120ms显示过渡，不预测远期轨迹 |
| 丢失保持 | 新结果暂时漏掉目标：车辆／行人最多650ms，车道最多850ms，淡化显示；采集证据总年龄上限1200ms |
| 清除 | 停止、断流、控制快照超500ms、无效感知、时间倒退、检测会话或服务变化清除；重复帧和重复HTTP读取不续期 |

候选车道的显示线型不替代原板端稳定线型；变道反馈继续使用原有确认和1.5秒保持逻辑。行人仅显示，不因出现行人即触发礼让；斑马线独立识别和行人过街关系属于后续任务。

所有新增跟踪、投影和2.5D绘图在Ubuntu预览执行；RK3568仍执行模型推理、车道解码和驾驶规则，只增加轻量打包转发。不会增加RK3568的模型推理次数。真实预览帧率、USB传输和Ubuntu CPU开销仍需实机验收。
