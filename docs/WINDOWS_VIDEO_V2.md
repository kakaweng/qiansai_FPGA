# Windows 视频识别与驾驶提示 v2.1

> 本文规则和旧 CPU 回放数据保留为基线。当前播放默认已改为原速播放＋后台分析，优先 DirectML GPU；最新性能及比赛要求差距见 [WINDOWS_PERFORMANCE.md](WINDOWS_PERFORMANCE.md)。规则版本仍为 v2.1。

## 1. 运行

```powershell
cd 'F:\B_file\jichuangsai\Pango_FPGA\09_pcie_test\pcie_host'
.\run_video_decision.cmd 'D:\buduinetdiskdownload\video_20260929_112507.mp4'
```

双击 `run_video_decision.cmd` 可选择其他视频。需要导出识别结果：

```powershell
py -3.11 video_driving.py 'D:\buduinetdiskdownload\video_20260929_113539.mp4' --save-video
py -3.11 verify_video_behavior.py
```

当前普通窗口默认原速播放，并独立运行后台分析。`--backend auto` 优先 DirectML GPU；无 GPU 时明确提示回退 CPU。无窗口默认离线分析，或显式加 `--playback offline`：该模式按采样帧完整处理，处理不足时窗口慢放。需要 Python 3.11、OpenCV、NumPy、Pillow 和两个现有 ONNX 文件；GPU 推理另需 `onnxruntime-directml`，不要求 CUDA 版 PyTorch。

| 操作 | 结果 |
| --- | --- |
| 点击预览窗口 | 取得键盘焦点 |
| Space / R | 暂停恢复 / 从指定起点重播并重置历史 |
| A / D | 单次判断左 / 右变道，大小写均可，暂停也可使用 |
| 再按 A / D | 用新画面及最近轨迹重新判断；旧结论不会自动修改 |

| T / Q / Esc | 框选信号区域 / 退出 |

## 2. 本轮规则

| 观测 | 提示与解除条件 |
| --- | --- |
| 路边或邻道行人无路径冲突 | 不触发停车礼让 |
| 路径外的行人向本车路径移动 | 注意行人，可能横穿 |
| 行人正在横穿已确认路径，尚远 | 减速、准备礼让 |
| 行人接近且占用已确认路径 | 停车礼让；确认脚底离开后立即解除 |
| 目标突然漏检 | 短暂显示注意观察，最长 500 ms；不将消失当作已确认离开 |
| person 与 bicycle/motorcycle 关联 | 按骑行者处理，骑行身份保持最多 1 秒，避免车框漏检后变成行人停车提示 |
| 线型未知、无其他减速/停车原因 | 普通行驶保持 NORMAL，附注证据缺失 |
| 请求跨实线、邻道近车/接近车、当前需停车 | 拒绝本次变道并显示全部原因 |
| 请求跨虚线、邻道范围与运动不明 | 立即回应无法判断 |
| 虚线、可见邻道存在且未发现冲突 | 提示可见区域未发现冲突，请确认侧后方；不记录为全面安全许可 |
| 红灯 | 尚远时减速准备停车；近端横线证据出现后停车，该次红灯内遮挡不会反复降为减速 |
| 信号未确认 | 注意观察；已见信号后短暂保留颜色最多 1.5 秒，持续缺失改待确认 |
| 绿灯 | 显示对应方向信号状态，仍受行人冲突规则限制 |

近远使用图像位置、目标框与横线证据；当前没有相机距离标定，不能解释为米或精确碰撞时间。识别到骑行者后仍参与邻道车辆判断，但本轮没有独立的前方骑行者碰撞决策。

## 3. 感知与模型契约

处理顺序：YOLOv5 目标框 → YOLOP 标线分割 → 边界几何与原图虚实线 → 方向信号 → 目标轨迹 → 行人/邻道/道路上下文 → `VideoBehaviorMonitor`。

| 项目 | 目标检测 | 车道分割 |
| --- | --- | --- |
| 文件 | `models/yolov5s.onnx` | `models/yolop-640-640.onnx` |
| 来源 | Ultralytics YOLOv5 v7.0 官方 ONNX | hustvl/YOLOP 官方 BDD100K 预训练权重 |
| 标签 | COCO80；驾驶入口使用 0/1/2/3/5/7/9 | 两个分割头各为背景、前景；不含实/虚线类别 |
| 输入 | RGB，640×640 letterbox 114，除以 255，NCHW | 同尺寸/RGB/letterbox，除以 255，再按 ImageNet mean/std 归一化，NCHW |
| 输出 | `[1,25200,85]`，框+objectness+80 类 | `det_out [1,25200,6]`、`drive_area_seg [1,2,640,640]`、`lane_line_seg [1,2,640,640]` |
| 解码 | objectness×类别概率，按类 NMS，去 padding 映射原图 | 请求全部输出；分割前景通道大于背景通道，去 padding，再 nearest 还原原图 |
| 模型精度/量化 | FP16 ONNX 输入/输出；OpenCV 接收 FP32 blob，DirectML 转为实际 FP16；未做 INT8 量化 | FP32；未做 INT8 量化 |
| 契约 | `models/yolov5s.onnx.json` | `models/yolop-640-640.onnx.json` |

YOLOP 的检测头和可行驶区域头不参与当前驾驶判断。标线分割只帮助定位，虚实线依然需要原图油漆连续性、可见间隙及多帧确认。不能把分割模型连接虚线空隙的预测当作实线证据。

YOLOv5 SHA256：`8bc25a47abdbe2fd23e30eb948746bf856b031ea3cc815166687f52db9f8c659`。

YOLOP SHA256：`cd66a3e0087a7258ae07768cc02cb742eed93865727ae4c9baf969b8fa190696`。

本轮接入预训练模型，没有用用户的三个视频或本地 BDD100K 再训练。两个模型不是可直接加载到 RK3568 的 RKNN 文件；上板还需转换、适配分割输出及实机验收。

`windows_video_112507.json` 的 `region` 控制标线证据搜索范围，`reference_row=0.94` 用于近端左右边界归属，避免在远端横截面上错误选择本车边界。近端参考行允许少量线段外推；虚实线只采样实际搜索区，外推部分不作为油漆证据。该参数仍需要针对安装位置核对。

信号先取 ROI 内的水平灯框，缺失时使用成对灯色几何，再判断圆灯或方向箭头；圆灯颜色写入三个方向的信号状态。地面箭头多帧确认，双向车道未确定意图时默认直行；背景运动只提供方向估计，强运动可较快确认转向，轻微转向不立即改变方向。道路弯曲、变道和相机抖动仍可能影响它，不能用该估计替代导航意图或完整车道信号关联。

## 5. 当前限制

车道分割改善了标线定位，完整走廊和虚实线仍有大量未知，尤其是路口没有纵向标线、前车遮挡、短划线和弯道。不得把输出计数当作准确率，或者为了减少未知直接宣称允许变道。

远处箭头分辨率不足时保留未知；第一个视频 9～13 秒的箭头灯尚不能保证每帧认清方向。停止线原型也可能把斑马线、阴影或其他横线当作近端参考；尚未训练停止线模型。尚未完成灯与具体车道的完整关联、侧后方感知、实际违规确认和车辆/FPGA 执行闭环。

Windows 主提示为 NORMAL/WATCH/SLOW/STOP。NORMAL 表示当前输入未发现需要减速或停车的冲突，不证明全面安全。变道 `visible_clear` 只表示可见前方范围；`turn_left/turn_right=signal_green` 只记录方向信号为绿，不是允许转弯。

旧板端 `decision_preview.py`、`driving_decision.py` 和人工模拟入口保留各自规则。Windows v2.1 的新轨迹/分割/决策尚未迁移到 RK3568。
