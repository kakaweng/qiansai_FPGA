下表使用相同的 3,198 个严格未横穿窗口，含 146 个“未来 1 秒首次横穿”正窗口。两个版本分别只在同一验证视频上选择阈值，选择规则均为负窗口误报率不超过 5% 时尽量提高召回；下表是开发回归结果，未强制把回归误报率设为 5%。

| 1 秒预测指标 | 第一轮 v1 | 第二轮 v2 |
| --- | ---: | ---: |
| 验证集选择的阈值 | 0.81 | 0.145 |
| 正确提醒窗口 TP | 32 | 36 |
| 错误提醒窗口 FP | 102 | 41 |
| 漏掉的正窗口 FN | 114 | 110 |
| 提醒窗口精确率 Precision | 23.88% | 46.75% |
| 正窗口召回率 Recall | 21.92% | 24.66% |
| F1 | 22.86% | 32.29% |
| 负窗口误报率 | 3.34% | 1.34% |
| 平均精确率 AP | 0.14369 | 0.33790 |
| 连续两次确认后的错误启动片段 | 20 | 8 |
| 有效 1 秒时间窗内存在确认提示的轨迹 | 7／34 | 8／34 |
| 在有效 1 秒时间窗内新启动提示的轨迹 | **7／34** | **7／34** |
| 仅因过早提示延续而获得覆盖的轨迹 | 0 | 1 |
| 有效新启动提示的中位提前量 | 0.500 秒，7 条 | 0.667 秒，7 条 |
| 每标注行人分钟的错误启动数 | 1.876 | 0.750 |

错误提醒窗口减少约 59.8%，错误启动片段减少 60%。这支持“本批开发视频的误提醒减少”，不支持“已经可以稳定提前预判横穿”。仍有 26／34 条可评估起点轨迹，在有效 1 秒窗内没有任何确认提示；若要求在该窗内新启动，则有 27／34 条未满足。

两个确认样本必须来自连续的独立 5Hz 时间点；重复帧不增加票数，采样间断重置确认。误启动按确认提示开始时是否落在正窗口判定。因此，提前 1.167 秒开始的提示可先计作一次错误启动，又因持续进入起点前 1 秒而计入“窗内存在提示”。这两项统计并不互斥，不能把后者全部解释成时机合适的新预警。

每标注行人分钟以严格队列的 639.6 个行人观察秒为分母，不等同于每分钟行车视频的报警次数。窗口也可能相互重叠，不能当成独立人数或事件。

第一轮原界面使用的 0.3 阈值仍存于原始指标中，属于历史参考。本报告用同一验证误报预算重新选得的 0.81 作为主要对比，以免把调高旧版阈值也可减少的误报全部算作新模型收益。

## 本轮重新定义的训练目标

第一轮的“未来 1 秒包含 crossing”同时包含已在横穿且继续横穿的样本。本轮单独建立首次横穿前任务，筛选规则如下。

| 项目 | 规则 |
| --- | --- |
| 官方起点 | 轨迹第一次出现逐帧 `crossing`，前一帧必须为 `not-crossing`，并连续至少 3 帧为 `crossing` |
| 无法确认的起点 | 首次出现时已经 crossing、缺少前一帧或转换不稳定，整条起点任务排除 |
| 历史完整性 | 检查过去 1 秒全部 31 个原始帧，必须连续、有已知动作且没有完全遮挡 |
| 历史动作 | 过去 1 秒没有 crossing；轨迹更早已经出现首次 crossing 的窗口也排除，即使当前恢复了 not-crossing |
| 严格主队列 | 历史动作均为 `not-crossing` |
| 无关横穿诊断 | 历史含 `crossing-irrelevant` 时单列；保留于训练池及总体开发指标，不混入严格主队列 |
| 未来完整性 | 两个预测任务均要求完整、连续且动作已知的未来 1 秒；缺少标注不当作负例 |
| 预测输入 | 每隔 0.2 秒采样一次，共 6 个历史时刻；图像、框及派生特征均截止当前时刻 |
| 预测标签 | 首次官方 crossing 起点是否分别出现在随后 18／30 个原始帧内，即 0.6／1 秒 |
| 禁止作为输入的资料 | 官方动作、意图属性、未来框／图像、未来 crossing 起点等，只用于构造或检查标签 |

**PIE 的 crossing 是相对原录像中本车路径的官方行为关系标签。它不一定等于行人从静止迈出第一步，也不提供用户改选左转／右转后的真实行为结果。** 案例中，一个已经在道路上行走的人仍可能暂时被标为 not-crossing。报告和图册中的“起点”均指首次官方标签转换。

0.6 秒任务与 1 秒任务共用完整未来 1 秒的候选池，便于同队列比较；代价是没有纳入部分仅有 0.6 秒可观察未来的尾端样本。

## 数据与训练

复用本地 7 段 PIE 视频及已经核对的历史特征缓存，并回到逐帧 XML 重建标签。视频、空间标注、属性标注及缓存的 SHA256 写入 [data_audit.json](runs/pie_behavior/anticipation_v2_20261101/data_audit.json)。原始视频和 XML 没有修改。

| 划分 | 视频 | 本轮全部窗口 | 严格未横穿窗口 | 无关横穿历史窗口 | 可用于 1 秒任务的起点轨迹 |
| --- | --- | ---: | ---: | ---: | ---: |
| 训练 | set01/video_0001～0003 | 3,770 | 3,679 | 91 | 32 |
| 验证、选型和阈值 | set01/video_0004 | 224 | 224 | 0 | 3 |
| 开发回归 | set02/video_0001～0003 | 3,251 | 3,198 | 53 | 34 |

训练池的 0.6 秒／1 秒正窗口分别为 87／142，验证分别为 9／15，严格开发回归分别为 85／146。表中最后一列是经过连续历史、可观察首次转换等条件筛选后，至少有一个有效 1 秒正窗口的轨迹数。

**set02 在此前工作中已用于评估及场景检查，本轮只能称开发回归集。** 没有新的独立未见测试集；按视频划分也不意味着不同视频中的行人身份已经做过跨视频排重。本轮没有根据 set02 分数更换候选或调整阈值。

训练前保存 [protocol.json](runs/pie_behavior/anticipation_v2_20261101/protocol.json)，预先固定三个候选、数据划分、自然比例验证 BCE 选型及阈值规则。训练不对正例额外增权；用轨迹窗口数平方根的倒数调权，降低很长轨迹的支配作用。最多 120 轮，验证误差连续 20 轮未改善则早停。

| 预先固定候选 | 输入与结构 | 最佳轮次 | 验证 BCE，越低越好 |
| --- | --- | ---: | ---: |
| **geometry，最终选中** | 历史框几何特征的当前值、均值、首尾变化，轻量分类头 | **96** | **0.195701** |
| visual_linear | 冻结视觉编码的 PCA16 特征＋几何统计，轻量分类头 | 62 | 0.241150 |
| temporal | 相同视觉／几何序列，12 维 GRU＋分类头 | 8 | 0.207435 |

现有样本下，带视觉／GRU 的候选没有胜过框几何基线。最终版本是依据已有行人跟踪框历史工作的轻量行为分类器，不能把它表述成重新训练了完整行人检测器。三个候选的最佳权重、选择记录和训练曲线均已保存于 [产物目录](runs/pie_behavior/anticipation_v2_20261101/)。

## 不同场景与 0.6 秒任务

1 秒任务的确认提示分布明显不均匀。下表来自各视频总体队列；正起点轨迹分母及确认覆盖与严格主队列一致。

| 开发视频 | 有效起点轨迹 | 窗内存在提示 | 窗内新启动提示 |
| --- | ---: | ---: | ---: |
| set02/video_0001 | 8 | 0 | 0 |
| set02/video_0002 | 20 | 2 | 1 |
| set02/video_0003 | 6 | 6 | 6 |

不能用第三段的结果代替所有场景表现。验证视频也只有 3 条有效起点，其中唯一一次确认提示仅提前 0.033 秒，不能证明模型具备稳定提前量。

| 新版严格开发回归 | 0.6 秒目标 | 1 秒目标 |
| --- | ---: | ---: |
| 验证选择阈值 | 0.16 | 0.145 |
| TP／FP／FN | 20／27／65 | 36／41／110 |
| Precision／Recall | 42.55%／23.53% | 46.75%／24.66% |
| 窗内存在确认提示 | 6／29 | 8／34 |
| 窗内新启动确认提示 | **1／29** | **7／34** |
| 仅过早提示延续的轨迹 | 5 | 1 |
| 错误启动片段 | 7 | 8 |

0.6 秒任务中的大部分覆盖来自过早提示延续，目前不能认为更短预测时间更可靠。下一轮开发应优先检查 1 秒目标的漏报原因及输入适用条件。
