**直接使用**

在 Windows PowerShell 执行，浏览器会自动打开本机播放器：

```powershell
Set-Location 'F:\B_file\jichuangsai\Pango_FPGA\09_pcie_test\pcie_host'

& '.\.venv-lane\Scripts\python.exe' rehearsal_player.py `
  --video 'F:\waymo_data\pie\set02\video_0002.mp4' `
  --profile pie
```

终端出现 `REHEARSAL_PLAYER_READY http://127.0.0.1:...` 后保留终端。可以先拖到约 **193.6 秒**，点击“冻结当前画面并识别”。程序读取截至当前时刻的过去 2 秒，完成真实模型推理、跟踪和新模型预测，然后在同一浏览器窗口进入预演；此处理不是实时识别帧率测试。

| 操作 | 行为 |
| --- | --- |
| 播放器时间条 | 自行选择待预演的路口时刻，至少在视频第 2 秒以后 |
| 冻结当前画面并识别 | 暂停原视频，处理历史图像，生成当前场景 |
| 左转／直行／右转，J／I／L | 切换模拟路线，并重置模拟时间 |
| 播放／暂停，空格 | 播放最多 3 秒的预演；目标初始位置来自当前真实检测 |
| 预演时间条 | 拖动查看不同时刻的位置与示意交汇 |
| “模拟范围交汇时，本车先等待” | 勾选时在最早模拟交汇前等待；取消可对比继续沿路线行驶 |
| 重置，R | 回到该冻结场景的起点 |
| 返回视频 | 回到原视频的暂停位置，可继续播放并选择另一个时刻 |
| 终端 Ctrl+C | 关闭本机服务；不操作板端服务 |

快捷键在按钮／输入控件有焦点时优先交给控件，可点击画面空白处后使用。当前播放器使用浏览器支持的 MP4 编码；不支持的编码请先另存为 H.264 MP4。

更换视频只需修改 `--video`。PIE 的 `--profile pie` 使用该来源的车头排除配置和近似显示投影；其他相机视频应去掉它，不能套用 PIE 的车头区域。此时使用全画面默认相对示意，新的真实地面标定尚未自动完成。

PIE 的 `annotations`／`annotations_attributes` 是行为和框标注。此次未发现官方相机外参、米制路面或可替换转向后的真实轨迹标签。`crosswalk` 官方框也不是贴地四边形，不能拿它直接训练斑马线像素分割或当成真实地面标定。

配对、特征缓存和窗口清单位于 [dataset_audit/pie_behavior_20261101](dataset_audit/pie_behavior_20261101/index.html)。

**这次训练了什么**

| 项目 | 合同 |
| --- | --- |
| 模型 | `pie_temporal_v1_20261101`，冻结现有公开预训练 MobileNetV3 视觉骨干，训练新的视觉投影、GRU 时序层和分类头 |
| 历史输入 | 6 个按 5Hz 采样的目标图像与检测框，覆盖过去 1 秒；外观与几何均为当前／历史信息 |
| 目标 | 随后 30 个原始视频帧中，是否出现官方逐帧 `crossing`；包含已经横穿且下一秒继续横穿的样本 |
| 辅助目标 | 当前 `not-crossing`／`crossing`／`crossing-irrelevant` 三类 |
| 标签边界 | `crossing-irrelevant` 保留为不同当前状态，不当成横穿本车路径；缺少未来标签不当作负例，完全遮挡历史窗口排除 |
| 防标签泄漏 | `intention_prob`、`crossing_point`、未来框、未来图像及动作标签均不作为模型输入；按训练数据计算归一化统计 |
| 训练 | Windows RTX 4060，训练到第 16 轮触发早停，验证 BCE 最好的第 1 轮保留；训练损失下降而验证误差升高，存在明显过拟合 |
| 运行差异 | 训练／测试指标使用官方标注框；实际预演输入使用 YOLO 跟踪框，存在检测误差和换 ID 的额外影响 |

**首轮实测指标与发布结论**

| set02 评估口径 | Precision | Recall | F1 | ROC AUC |
| --- | ---: | ---: | ---: | ---: |
| 所有有效窗口，固定阈值 0.5 | 52.98% | 80.03% | 63.75% | 0.8539 |
| 所有有效窗口，验证集选择阈值 0.3 | 44.49% | 92.72% | 60.13% | 0.8539 |
| 仅当前尚未标为 crossing 的窗口，阈值 0.3 | **6.52%** | **77.71%** | **12.04%** | 0.7403 |

最后一行最接近“提前预判”的要求：3,895 个窗口中只有 157 个未来正例，模型报出 122 个真阳性和 1,748 个假阳性，提前提醒的误报明显过多。前两行包含已经横穿的样本，不能用它们宣传提前预判成功率。没有进行概率校准；UI 显示的是模型分数，不是概率。

**发布结论：模型仅用于实验分数展示，未达到自动礼让／停车触发条件。** 当前路线交汇分析不读取这个分数，因此调整分数或高分误报不会直接让模拟／真实车辆获得通行许可。报告中另有使用官方当前动作标签的持续状态参考；它是诊断用特权参考，不是线上可用基线。

完整指标：[metrics.json](runs/pie_behavior/temporal_v1_20261101/metrics.json)。版本、标签顺序、裁剪／归一化、输入输出布局、FP32 量化状态、解码器、划分、代码和模型哈希均写入 [behavior.manifest.json](runs/pie_behavior/temporal_v1_20261101/behavior.manifest.json)。

导出为 `appearance.onnx`（约 11.9 MB）和 `forecast.onnx`（约 0.27 MB）。PyTorch 与 ORT 最大绝对误差：时序输出不超过 3.58e-7，视觉编码不超过 9.54e-6，已检查批量输入；未转换 RKNN，也未计入 RK3568 NPU 性能。

**2.5D 预演实际做到了哪里**

| 层次 | 已实现 | 限制 |
| --- | --- | --- |
| 当前目标 | 原 YOLO＋现有跟踪器，当前画面和 2.5D 使用相同 ID；只有有效落点进入地面映射 | 不直接绘制官方框作为识别结果；换 ID、检测漏掉、位置未知仍会影响显示 |
| 车道／斑马线 | 原车道模型及 C 解码器导出当前曲线；独立斑马线 ONNX 产生当前区域 | 路口无车道线就不补造真实道路；斑马线为当前预测，不是精确完整拓扑 |
| 路线 | 用户选择的三条示意曲线，统一从模拟本车起点出发 | 未自动识别真实出口、转弯半径或车道约束；不是重建的真实行驶路线 |
| 周围目标运动 | 对背景运动补偿后的短时目标位移作显示推演；不可靠时速度未知、扩大示意范围 | 多数目标当前仍缺稳定运动，6 场景各只有 0～2 个目标满足这项短时运动条件；没有把未知当作静止真值 |
| 交汇与等待 | 对模拟路线与目标示意范围作时刻对照，标出相交位置；可对比等待／继续 | 是假设下的范围接近，不是实测碰撞时间或避撞算法；停车演示不会自动恢复，需用户重置或切换对比 |
| 时间 | 3 秒可播放、暂停、拖动和重置；新行为模型只预测其中未来 1 秒的行为标签 | 余下 2 秒是延续运动假设，不是训练出的 3 秒轨迹；行人不会响应本车反事实动作 |
| 地面 | 默认相对映射；为 PIE 画面单独选定近似道路显示参考，避免旧通用投影把目标挤在车前 | [pie_rehearsal_projection.json](pie_rehearsal_projection.json) 标记 `calibrated=false`；不是官方相机标定或米制坐标，不能复制到其他相机 |
| 操作范围 | Windows 本机播放器和交互页面，沿用深蓝中文卡片视觉 | RK3568 上的 `preview_front_p1.sh` 尚未增加本轮功能，现有实机运行方式不变 |

六个冻结场景来自 set02：video_0001 的 407.8／523.4 秒，video_0002 的 193.6／285.4 秒，video_0003 的 39.6／47.8 秒。每个场景执行 11 个历史采样，共 66 次真实 YOLO 和车道推理；冻结帧另跑斑马线，行为模型只使用过去的检测历史。官方标签仅用来选取有意义的开发片段，不作为预演目标位置、分数或运动输入。
