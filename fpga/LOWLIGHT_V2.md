# FPGA暗光增强v2（2026-11-02）

本版以实体灯反馈位流为基础，替换原先按亮度4倍/2倍/1.25倍跳变的暗光算法。处理继续由FPGA像素流水线完成；不新增训练模型，不增加整帧等待。原方向键、灯光接口及三路采集保留。

## 操作与展示链路

| 操作 | 行为 |
| --- | --- |
| KEY1 | 原六模式循环保持：原彩色→灰度→中值→二值→边缘→暗光→原彩色；上电初始灰度，从该初始状态按4次到暗光 |
| 暗光模式 KEY2 | 增强强度提高一级，最高LOW 3 |
| 暗光模式 KEY3 | 增强强度降低一级，最低LOW 1 |
| 其他模式 KEY2/KEY3 | 原二值/边缘阈值增减，默认110、每次4；与暗光强度分开保存 |
| 左上 `LOW 1/2/3` 标记 | 弱/中/强，默认中档；只有FPGA暗光输出才出现，可据此核对当前模式 |
| KEY4、KEY5/6/7 | 保持原UDP开关及左转/直行/右转功能 |

强度经两级同步、在帧同步边界更新，避免调强度时同一帧上半/下半使用不同曲线。达到上下限继续按不会循环跳档。模式切换沿用原KEY1功能。

| 链路 | 本轮行为 |
| --- | --- |
| FPGA物理HDMI输出 | 暗光模式使用新算法并显示LOW档位标记 |
| 原FPGA彩色UDP抓图分支 | 暗光模式跟随同一输出，含LOW标记 |
| PCIe→RK3568推理/Ubuntu预览 | 保留原始RGB565输入；不把暗光增强画面或LOW标记送入识别模型 |
| 摄像头/以太网输入及三路展示 | 采集方式保留，本轮只改HDMI增强分支 |

因此不能用Ubuntu原彩色预览来判断增强已生效。请看FPGA物理HDMI输出，先确认左上LOW标记。后续要让模型吃增强图像，需另做输入对比和准确率验证。

## 算法

| 部分 | 实现/目的 |
| --- | --- |
| 轻量降噪 | 水平方向三像素1:2:1加权；中心最大通道小于112、两邻点各通道差都不超过12才滤波；保护车道线和强边缘，行首尾不混入消隐像素 |
| 平滑提亮 | 256项、三档曲线；离线生成严格非递减的整数目标值，无旧阈值处的亮度倒退 |
| 近黑保护 | 0保持0；最低亮度逐渐进入增强，减少把极暗噪点直接放大4倍的问题 |
| 高光保护 | 增益随最大颜色通道接近255平滑收回1倍，不对灯具继续固定乘1.25倍；已过曝的细节无法恢复 |
| 颜色 | RGB共用最大通道查出的Q8增益，保持通道比例；生成表保证最大通道不溢出，无三个通道独立硬截断 |
| 时延/存储 | 模块10个像素时钟，顶层原输出寄存器另1拍；一像素/时钟，无整帧缓存，滤波只存相邻像素 |

曲线由 `tools/generate_lowlight_lut.py`生成，ROM文件为 `src/hdmi_lowlight_gain_rom.v`；整数参考为 `tools/lowlight_reference.py`。强度为人工三档，没有按帧直方图自动调亮，也没有使用未来帧或视频预置结果。

只有水平轻量降噪；不把它描述成完整二维/时域去噪。原视频中已有明显彩色噪点与压缩损失，增强后仍可能可见；更强去噪需要另评估资源与细节损失。

## 同帧对照与验证

浏览 [同帧对比页面](lowlight_review_20261102/index.html)，或播放 [原图/旧算法/新中档对比视频](lowlight_review_20261102/night_raw_legacy_v2.mp4)。页面另有1、7、14秒的弱/中/强全尺寸PNG及四宫格。

这些是与RTL核对过的整数参考输出，不是FPGA实机采集。处理在原片1920×1280上进行，再缩放显示；原片约9.9 FPS，193帧完整导出，不用重复帧提高标称帧率。

| 检查 | 结果 |
| --- | --- |
| 像素与时序 | 218,573个测试向量通过；三档全灰阶、随机RGB、真实夜间帧、边界/消隐、HS/VS/DE、帧内改强度；输出与整数参考逐像素一致 |
| 曲线 | 三档256项均非递减；黑白端点保持，输出无溢出 |
| 合成暗部噪声 | 固定噪声样本中，滤波后标准差约为仅提亮的0.636倍；只用于确认滤波作用，不代表真实视频去噪准确率 |
| 实片高光 | 抽查1/7/14秒三帧，新三档达到255的通道比例均与原图相同；旧算法明显增加。完整数值见 `lowlight_review_20261102/review.json` |
| 原按键 | 实际顶层验证六模式、新暗光档位上下限、原阈值保存、方向键隔离通过 |
| 顶层输出 | 实际例化hdmi_loop，确认HDMI/UDP增强、原彩色旁路、11拍同步延迟、PCIe原RGB565保持 |
| 实体灯RTL | 礼让/停车/方向/报警、心跳、超时、极性及寄存器隔离通过 |

第一轮时序定位到ROM输出经过档位选择直接进入DSP的路径不足，增加独立一级寄存器；第二轮将档位文字绘制拆成两级，避免OSD成为像素域瓶颈。逐像素/同步/档位/实际顶层测试随修改复跑，增强数值保持不变。最终构建目录为 `../lowlight_build_final_20261102/`；早期两个构建目录仅保留诊断记录，其位流未发布。

构建与完整视频回归的最终状态记录在 [LOWLIGHT_V2_BUILD.md](LOWLIGHT_V2_BUILD.md)。不把参考图或RTL仿真当作实机验收。

## 上板测试

1. 在PDS下载器下载独立新位流 `hdmi_loop.lowlight_v2.sbit`；旧 `hdmi_loop.drive_feedback_v1.sbit`及三路位流保持可回退。
2. 只看物理HDMI输出时，让Windows继续将夜间视频全屏输出到FPGA输入；KEY1切到左上出现LOW 2的暗光模式。
3. 同一暂停画面核对LOW 1/2/3，观察路面与标线清晰度、噪点、灯具颜色；KEY1下一模式回到原彩色进行比较。
4. 连续播放观察调档是否有明暗接缝，快速车辆/车道线是否拖影，原KEY1～4、方向键及灯光是否保持。
5. 如果还要使用RK单路识别/实体灯，保持FPGA供电，重新枚举PCIe并恢复原驱动、前视、方向键和灯光服务；依旧使用 `preview_front_feedback.sh`，无需重训或重装模型。

夜间素材：`../09_pcie_test/pcie_host/demo_cases_20261102/06_night_enhancement/front.mp4`。最终以上板输出为准；若左上没有LOW标记，先核对当前位流与模式，不继续盲调参数。
